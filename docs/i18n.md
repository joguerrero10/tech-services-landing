# Internacionalización de la landing

La URL determina el idioma. `core/config/site.config.ts` centraliza los idiomas y su mapeo; `core/i18n/locale.config.ts` los expone a los consumidores:

| Ruta  | Diccionario y `html[lang]` | Locale de números |
| ----- | -------------------------- | ----------------- |
| `/es` | `es`                       | `es-ES`           |
| `/en` | `en`                       | `en-US`           |

`/` redirige a `/es`. Las rutas desconocidas, incluidos idiomas no admitidos y subrutas inexistentes, redirigen a `/es` mediante el comodín final. No se generan nombres de archivo ni peticiones a partir de segmentos arbitrarios. Solo se ofrecen Español y English, respetando la indicación de eliminar el tercer idioma.

## Carga antes del contenido

`LocalTranslationLoader` importa ambos JSON dentro del bundle y devuelve observables locales. No depende de HTTP, `window`, almacenamiento ni acceso al sistema de archivos en ejecución.

Cada ruta tiene un resolver que espera `TranslateService.use()` antes de activar la landing. `LanguageService.activate()` establece el idioma, el locale numérico, `document.documentElement.lang`, título, descripción y etiquetas Open Graph. La navegación inicial es bloqueante. El estado se mantiene en servicios de la instancia de Angular, sin variables globales mutables compartidas entre solicitudes.

Los mismos diccionarios y la misma ruta pueden utilizarse al prerenderizar. No se detecta el idioma del navegador ni se lee una preferencia durante la activación: eso evita que cliente y servidor elijan idiomas distintos para una misma URL. La prueba de plataforma servidor confirma que la resolución no accede al almacenamiento del navegador.

**Prerender e hidratación:** Angular genera `/es` y `/en` con diccionarios locales y resolver de idioma compartido con el navegador. La navegación inicial usa la configuración compatible con `provideClientHydration`. Los importes calculados con Intl se incorporan a TransferState para reutilizar exactamente los mismos textos al hidratar. La raíz redirige a `/es`. Ver `docs/seo-prerender.md` para servir los archivos sin fallback SPA.

## Diccionarios y cobertura

`src/app/core/i18n/locales/es.json` y `en.json` contienen estos grupos:

`identity`, `navigation`, `language`, `hero`, `services`, `applications`, `process`, `contact`, `footer`, `accessibility`, `seo`, `whatsapp`, `errors`.

Todo texto visible y accesible sale de esos diccionarios, incluidos estados, nombres de producto y mensajes preparados para WhatsApp. SmartFinance PTY y SmartPOS PTY conservan su escritura. Las frases de equipo usan plural. El título del hero es una frase completa traducida; no se unen fragmentos para formar una oración. `hero.titleHighlight` indica la frase que debe resaltarse dentro de `hero.title`. El pipe puro `HighlightTextPipe` localiza esa frase y devuelve segmentos de texto; la plantilla aplica terracota a un span sin usar HTML del JSON. El orden, los espacios y la puntuación del título completo se conservan, también si cambia la posición del énfasis. Si no hay coincidencia, se muestra el título completo sin resalte.

No se usa `innerHTML` para traducciones. Las frases se renderizan como texto mediante `TranslatePipe` con interpolaciones. Los catálogos almacenan claves completas con el tipo `TranslationKey`; no se construyen claves concatenando cadenas.

## Tarifas y condiciones

`core/config/services.config.ts` contiene los valores numéricos y estados, con identificadores `tutoring`, `python-course`, `development` y `maintenance`. Los importes no están escritos en las traducciones ni los componentes.

`core/i18n/service-interpolations.ts` calcula la duración del curso (`sessions × hoursPerSession`) y el ejemplo de desarrollo (`exampleHours × referenceHourlyRate`). Formatea importes con `Intl.NumberFormat`, `currency: 'USD'`, `currencyDisplay: 'code'` y dos decimales. No convierte monedas. Por ejemplo, una misma tarifa se presenta como `30,00 USD por hora` o `USD 30.00 per hour`.

Las unidades, condiciones y frases completas pertenecen a i18n. El paquete de tutorías muestra sus horas e importe sin presentarse como descuento; la prueba verifica que su precio equivale al de las horas individuales. El curso conserva el estado próximo y la condición de validar antes su contenido mediante tutorías. La configuración de aprobación de trabajo adicional determina la condición correspondiente de mantenimiento.

## Selector, secciones y estados

El selector nativo funciona con teclado y muestra los nombres completos Español y English. Navega a la ruta correspondiente y conserva el fragmento de sección cuando existe. Los enlaces internos usan `RouterLink` y `fragment` para conservar `/es` o `/en` a pesar del `<base href="/">`. Los identificadores de sección son estables entre idiomas.

La elección se guarda en `localStorage` con la clave `landing.language`, dentro de una comprobación de plataforma y un bloque `try/catch`. Una denegación de almacenamiento muestra un estado traducido y no impide navegar. La preferencia guardada nunca reemplaza la ruta: también la raíz tiene una redirección explícita a español. Por ello no se utiliza la preferencia para decidir la carga inicial.

Durante el cambio se deshabilita temporalmente el selector. Selecciones inválidas y navegación fallida muestran mensajes traducidos; el control vuelve al idioma activo. Los estados se anuncian mediante `role="status"`.

Cuando falta el contacto, se muestra el estado pendiente traducido; cuando la configuración es inválida, se muestra el error traducido sin crear un enlace ni romper el renderizado. La validación de números y codificación de mensajes siguen en `ContactService`. Ninguna comprobación envía mensajes a WhatsApp.

## Validación

```bash
npm run check:i18n
npm run test:i18n-validator
npm run test:ci
npm run typecheck
npm run build
```

`check:i18n` verifica igualdad de claves, hojas de texto no vacías, igualdad de nombres de interpolación y existencia de claves utilizadas en las plantillas y literales de TypeScript. También rechaza HTML en las traducciones. El escaneo distingue expresiones vinculadas como `[name]="item.icon"` de claves de texto. La comprobación de tipos complementa el escaneo para catálogos e inputs dinámicos. Mantener claves completas y tipadas, sin concatenación, permite esta verificación estática.

Las pruebas del validador introducen claves ausentes, interpolaciones distintas, texto vacío y HTML para comprobar que se detectan. Las pruebas Angular cubren entradas directas, redirecciones, prioridad de ruta, almacenamiento bloqueado, metadatos, selector, secciones, cálculos monetarios y estados de contacto.

Comprobación en navegador: español e inglés a 320, 390, 640, 768, 1024, 1280 y 1440 píxeles, sin desbordamiento horizontal ni interpolaciones pendientes. Evidencia en `qa/i18n-responsive.json` y `qa/i18n-mobile-menu-en.png`. El menú permanece en el flujo; Escape cierra y devuelve foco al botón.

Referencias: [resolvers de Angular](https://angular.dev/guide/routing/data-resolvers), [API de ngx-translate](https://ngx-translate.org/reference/translate-service-api/), [Intl.NumberFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat).

Los mensajes de WhatsApp se seleccionan por `ContactInquiry`, nunca comparando títulos. Las dos aplicaciones comparten `whatsapp.application` con `{{productName}}`, y el servicio lee el idioma activo para invalidar los enlaces calculados al cambiarlo. Los mensajes hablan desde la persona interesada; el contenido descriptivo del equipo sigue en plural.
